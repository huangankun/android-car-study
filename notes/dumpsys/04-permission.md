# dumpsys 存档：04-permission（讲解版 · 原命令是死命令）

命令：`adb shell dumpsys permission` → **输出为空**（shell 和 root 都试过，exit 0，无报错）

**为什么空**：Android 10 起 PermissionController 独立成了一个 App，`permission` 这个服务名退化成 `IPermissionController` 遗留桩，没有 dump 实现（`service list` 里能看到 `permission: [android.os.IPermissionController]`，但真身 `permissionmgr` 在这个镜像上也无输出）。**这条命令是计划附录 B 里的过时命令，Android 14 上已经死了。**

**正确替代**：`pm list permissions -g`（按组列出全部权限）。下面是真实输出的讲解。

## 逐段讲解（pm list permissions -g）

### 1. 权限分组结构：group → permission

```text
All Permissions:

group:com.google.android.gms.permission.CAR_INFORMATION
  permission:com.google.android.gms.permission.CAR_VENDOR_EXTENSION
  permission:com.google.android.gms.permission.CAR_MILEAGE
  permission:com.google.android.gms.permission.CAR_FUEL

group:android.permission-group.HEALTH
  permission:android.permission.health.READ_RESTING_HEART_RATE
  permission:android.permission.health.WRITE_STEPS
  ...
```

**讲解**：权限按「组」组织。`-g` 参数就是按组列出。每个 `group:` 下面挂若干 `permission:`。注意第一组 `CAR_INFORMATION`——这是 Google 为汽车场景定义的权限组（车架号扩展、里程、油耗），**正好是你座舱方向会打交道的权限**。系统会把你声明的权限归组，在设置页按组显示、按组授权。

### 2. 危险权限 vs 普通权限

```text
Dangerous Permissions:
  permission:com.google.android.providers.talk.permission.WRITE_ONLY
  permission:com.google.android.gm.permission.READ_CONTENT_PROVIDER
  ...
```

**讲解**：`pm list permissions -d`（`-d` = dangerous）只列**危险权限**——运行时需要弹窗向用户申请的（摄像头、定位、通讯录等）。普通权限（normal）安装时静默授予，危险权限必须在运行时申请。**面试常问「normal / dangerous / signature 权限的区别」：dangerous 要运行时弹窗，signature 要同签名才能授，这是 Android 权限模型的三个 protection level。**

### 3. 替代命令汇总（记这三个就够）

```bash
pm list permissions -g          # 按组列全部权限
pm list permissions -d          # 只列危险权限
dumpsys package <包名>           # 看单个包请求/声明的权限（第 03 档讲过）
```

**一句话结论**：Android 14 查权限不用 `dumpsys permission`，用 `pm list permissions` 系列 + `dumpsys package`。`pm list permissions -g` 里的 `CAR_INFORMATION` 组是你座舱方向该眼熟的。
