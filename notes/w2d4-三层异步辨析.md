# W2 黄金链路 · 三层异步辨析

> 复习记录：把 `setProperty` 的同步抛错、事后 `onPropertySetError`、事件推送 `onPropertyChange` 三条路的区别讲清楚。
> 对应源码：W2D3 `VehicleHal.java`（set/onPropertySetError/onPropertyEvent），W2D4 `CarPropertyManager.java`（handleCarServiceSpecificException）

## 三条路，一张表

| | 路 A：`code 4` 拒绝 | 路 B：`onPropertySetError` | 路 C：`onPropertyChange` |
|---|---|---|---|
| **触发方** | App 调 `setProperty` | VHAL（事后 CAN 故障） | VHAL（值变化） |
| **App 是否阻塞** | **是**，同步等 | 否 | 否 |
| **App 怎么收到** | **当场抛异常** | 异步回调 `onErrorEvent` | 异步回调 `onChangeEvent` |
| **和调用栈关系** | 在 `setProperty` 调用栈上 | 无关 | 无关 |
| **代码落点** | `VehicleHal.set()` → 抛 `ServiceSpecificException` | `VehicleHal.onPropertySetError` → `client.onErrorEvent` | `VehicleHal.onPropertyEvent` → `client.onEvent` |
| **W2D2 实验** | `set-property-value 0x11400400` → `(code 4)` | 未触发（需要真实 CAN 故障） | `get-property-value` 可读，`inject-vhal-event` 也走这里 |

## 和 W2D2 实验的联系

- 写只读属性（`set-property-value 0x11400400`）走的是 **路 A**：VHAL 当场拒，同步抛 `code 4`，经 `handleCarServiceSpecificException` 翻译成 `PropertyAccessDeniedSecurityException`。
- `inject-vhal-event` 走的是 **路 C**：伪造 `onPropertyEvent`，投给订阅者，`get()` 看不到。
- 路 B 在当前模拟器上未触发过——它需要「VHAL 先接受、事后 CAN 报失败」才能走到。

## 记忆口诀

> **当场拒是同步抛，事后败是回调报，值变化是主动推。**
> 三条路分属三种场景：权限/属性定义问题（A）、硬件执行失败（B）、正常数据流（C）。
